# Mario (Godot Port)

An idiomatic **Godot 4.7** rewrite of the HTML/JS "SMB World 1-1 homage".
Same level layout, enemies, power-ups, coins, flagpole finish, music and
sound — rebuilt with Godot nodes instead of a hand-rolled canvas engine.

## Run it

1. Open **Godot 4.7**, click *Import*, and select this folder's `project.godot`.
2. Press **F5** (Play).

Or from the command line:

```
Godot_v4.7-stable_win64.exe --path "D:/best game/mario_godot"
```

## Controls

| Action | Keys |
| ------ | ---- |
| Move   | `←` `→` / `A` `D` |
| Jump (A) | `X` / `Space` / `↑` (hold for a higher jump) |
| Run / Fire (B) | `Z` / `Shift` — hold to run; a fresh press shoots a fireball as fire Mario (like Mario 1's B button) |
| Restart| `R` |
| Mute   | `M` |

## Power-ups

Bump a **mushroom block** as small Mario and it releases a **mushroom** →
super (big) Mario. Bump one while already big and it releases a **fire
flower** → fire Mario, who can shoot fireballs with `C` (max two on screen;
they bounce along the ground and knock out enemies). Any enemy hit drops you
one stage — fire → small, big → small, small → dead.

## How it's built (idiomatic Godot)

| Piece | Node / approach |
| ----- | --------------- |
| **First level** | **`Level1.tscn`** — a `TileMapLayer` ("Terrain") holding all 599 tiles *with* per-tile collision, plus a `Spawns` node of `Marker2D` points (`PlayerStart`, `Enemies/*`, `Coins/*`). Open it in the editor to edit the level visually. |
| Tileset | `tiles.tileset.tres` (atlas `tiles.png`) — one 16×16 tile per terrain type, each with a full-cell physics polygon on the world collision layer |
| Level manager | `main.gd` (`Node2D`) — instances `Level1.tscn`, reads its spawn markers, drives camera / HUD / audio, resolves entity-vs-entity hits |
| Player | `player.gd` (`CharacterBody2D`) — `move_and_slide`, variable-height jump, grow/shrink, death, flagpole win sequence |
| Enemies | `enemy.gd` (`CharacterBody2D`) — goomba & koopa, patrol + wall-turn, stomp → flat / shell |
| Mushroom | `mushroom.gd` (`CharacterBody2D`) — emerges, walks, is collected |
| Scenery / deco | `tile_renderer.gd` (`Node2D._draw`) — two instances: parallax clouds & hills behind the terrain, and the flag, castle detail, coins & particles in front |
| HUD | `hud.gd` (`CanvasLayer`) — score / coins / world / time + COURSE CLEAR overlay |

Bumping a `?`/mushroom block swaps its tile to the "used" tile via
`TileMapLayer.set_cell`; smashing a brick as big Mario calls `erase_cell`,
which drops the tile *and* its collision. A death or restart re-instances
`Level1.tscn`, restoring every block.

Rendering is a 256×240 viewport scaled up with nearest-neighbour filtering
for a crisp pixel look. Player/enemy/item/pipe art reuses the original PNGs in
`sprites/`; music and SFX are the original WAVs in `audio/`.

### Regenerating the level scene

`Level1.tscn`, `tiles.tileset.tres` and `tiles.png` are generated by two
headless build tools (edit the level layout in `tools/build_level.gd`, then):

```
Godot_v4.7-stable_win64_console.exe --headless --path . -s tools/gen_tiles.gd   # paints tiles.png
Godot_v4.7-stable_win64_console.exe --headless --path . --import                # imports it
Godot_v4.7-stable_win64_console.exe --headless --path . -s tools/build_level.gd # builds tileset + Level1.tscn
```

You can also just edit `Level1.tscn` directly in the editor — the tools are
only needed to regenerate it from scratch.

### Cross-class typing note

`main.gd` has `class_name Main` and instances the entity classes, while the
entity scripts hold their `main` reference **untyped**. That one-directional
dependency (Main → entities) is deliberate: typing `main: Main` in the children
too would form a cyclic `class_name` dependency that GDScript can't resolve at
parse time. A handful of locals derived from `main.*` are therefore typed
explicitly.
